## 2. 最初に完成させる範囲

「田んぼを作る → 4マスを書く → 要素を3つ埋める → 子の田を作る → 入れ子を移動する → 再起動しても残る」をMVPの到達点にする。

- 固定6種類の型、未完表示、作成日時、Three Good Thingsの主題への日付入力。
- 最大4階層、親の要素と子の主題の内容共有。
- 段階ズーム、子のタップ、パンくず、周囲の田のタップによる移動。
- 端末内への保存、保存失敗の表示、操作単位のUndo。
- 田んぼ一覧を入口にして、作成・再表示・削除を行えるようにする。

親を作る操作、ブランチ、双方向リンク・参照、発展、別表示、書き出し、CloudKit同期などは後続段階。MVPでは第4層の先へ進む操作や、未実装の親作成ボタンを表示しない。

## 3. Xcodeプロジェクトの方針

- XcodeのiOS Appとして `NewDen.xcodeproj` を作成。SwiftUI、SwiftData、Swift 6言語モードを使用する。
- 最低対応OSは **iOS 26.0を提案**。既存仕様には指定がないため、これは新しい実装上の前提。まずiPhone向けに仕上げる。
- `NewDen`、`NewDenTests`、`NewDenUITests` のターゲットを用意し、共有Schemeを保存する。
- 外部ライブラリは追加しない。Xcode標準プロジェクトで進める。
- CloudKit同期は無効にしたローカル保存から開始。モデルの既定値・optional関係など、将来の同期を見据えた設計は維持する。
- Bundle Identifierはプロジェクト作成時に定める。実機検証時にユーザーの開発Teamを設定する。
- `.gitignore` にDerivedDataやユーザー固有のXcode設定を追加する。

想定する構成:

```text
NewDen.xcodeproj
NewDen/
  App/                  アプリ起動、ModelContainerの構成
  Models/               Paddy、Den、Slot、Content、DenKind
  Persistence/          初版スキーマ、移行計画、Preview用データ
  Features/
    PaddyList/          田んぼ一覧、作成
    DenEditor/          マス編集、型選択
    NestedBoard/        配置計算、段階移動、パンくず
  Operations/           DenStore、操作エラー、Undoの単位
  Resources/            アセット、日本語表示文言
NewDenTests/
NewDenUITests/
```

表示はSwiftUI、保存変更は `DenStore`、座標計算は副作用のない処理に分ける。現在の田・選択マス・ジェスチャーの状態は表示用の状態として持ち、保存モデルに混ぜない。

## 4. 実装の順序と完了条件

| 段階 | 実装するもの | 完了条件 |
|---|---|---|
| 1. 起動基盤 | Xcodeプロジェクト、空の一覧、保存コンテナ、テストターゲット、Preview | Simulatorで起動し、ビルドと最小テストが通る |
| 2. 保存と操作 | 4モデル、6種類の型、VersionedSchemaとSchemaMigrationPlan、DenStore | 作成・編集・子作成・削除を保存し、再読込後も不変条件が成り立つ |
| 3. 1つの田の編集 | 一覧、新規作成、2×2表示、編集シート、未完状態、型選択、Undo導線 | 1つの田を最後まで書けて、編集1回をUndoできる |
| 4. 入れ子表示 | 最大40個の配置、段階移動、パンくず、周囲の表示、文字省略 | 最大4階層を移動でき、どの位置からも上位へ戻れる |
| 5. 品質確認 | 再起動、削除とUndo、保存エラー、文字サイズ、VoiceOver、Reduce Motion | 下記の受け入れ確認を満たし、日常利用できる |

### 段階2: 保存処理を先に確かめる

- 各田に位置1〜3のSlotを作り、表示時には必ずposition順に並べる。
- 最上位の主題は `themeContent`、子の主題は `parentSlot.content` を使う。子の主題用Contentは重複作成しない。
- 空白・改行のみも未入力として判定する。子作成条件と階層上限は画面とStoreの両方で守る。
- 変更時にContent／Den／Paddyの必要な更新日時を更新する。共有される親要素と子主題の両方への影響を含める。
- 保存成功・失敗を明示的に扱う。保存失敗時に編集内容を失わず、再試行できるようにする。
- 削除は子孫のcascadeと未使用Contentの後片付けを含めて検証する。最上位を消す場合はPaddy自体を削除し、空の田んぼを残さない方針を提案する。
- Undoは最初からModelContextに接続する。1操作に伴うモデル・関係・後片付けをひとまとまりにし、Undo／Redo後の再保存・再読込も試す。

### 段階3: 編集の境界を明確にする

- マス編集はシート内の一時的なテキスト状態を使い、画面からモデルを直接書き換えない。
- 「完了」でStoreに反映する編集を1回のUndoとする。キャンセルでは保存データを変更しない。バックグラウンド移行時は入力済みの下書きを確定して保存する方針とし、二重確定を防ぐ。
- Three Good Thingsの日付は最上位の新規作成時、または空の主題でその型へ変更したときに入れる。子の主題や入力済みの主題は上書きしない。
- 子のある要素をタップしたら子へ移動し、その主題から元の要素を編集できるようにする。
- 型変更の可否は設計書の操作表に合わせて「現在未完か」で判定する案とする。「一度完成したら空欄に戻しても永久に型固定」が意図なら、履歴を保存する属性が必要なのでモデル確定前に仕様を揃える。

### 段階4: モックの段階ズームをSwiftUIへ移す

- 田んぼ全体の正規化座標を計算し、選択中の田に合わせて表示範囲を変換する。周囲の田は薄く見える余白を確保する。
- 座標計算とタップ対象の判定を描画から分離し、境界上や深い子をタップした場合も直下の子へ1段だけ入るようにする。
- ピンチ開始位置と倍率を使い、1ジェスチャーにつき1段だけ移動する。モックの閾値（入る1.3倍、戻る0.77倍）を初期値として実機で調整する。
- 文字省略はモックの62pxを固定移植せず、約62ptを出発点に端末幅・文字サイズで調整する。深い田は形を残し、入った後に読めるようにする。
- 小さいマスや薄い周囲だけに操作を依存させず、パンくずとVoiceOverの移動アクションからも操作できるようにする。
- Reduce Motionでは大きなズーム移動を抑える。文字入力とピンチの競合も確認する。

## 5. 検証計画

保存ルールと座標計算はSwift Testing、主要画面の遷移はXCUITest、ピンチや読みやすさはSimulator・実機で確認する。

| 対象 | 確認する振る舞い |
|---|---|
| 生成と永続化 | 最上位1つ、Slot3つ、位置の一意性、再読込後の親子関係と並び順 |
| 子作成 | 要素0〜2個では不可、3個で可、空白だけは不可、既存の子への二重作成不可、第5層は不可 |
| 内容共有 | 子の主題編集が親の要素へ反映され、再起動後も同じ内容を指す |
| 型と日付 | 固定6種類、未完時の型変更、完成時の禁止、Three Good Thingsの日本語日付と上書き防止 |
| 削除とUndo | 子孫と未使用Contentの後片付け、最上位削除、1回で関係ごと復元、Redo、保存後の整合性 |
| 編集 | 日本語変換、長文、改行、完了・キャンセル、バックグラウンド移行、保存失敗時の入力保持 |
| 移動と表示 | 4階層・最大40個、ピンチの多重発火防止、パンくず、周囲のタップ、最上位での戻る操作 |
| アクセシビリティ | 大きい文字、VoiceOverで編集・階層移動、Reduce Motion、未完を色だけで区別しない |

メモリ内ストアのテストに加えて、一時ファイルのストアを閉じて開き直す永続化テストを行う。SimulatorはiOS 26.2と27.0、小さめのiPhoneと大きいiPhoneを使う。対応下限26.0そのものの検証はランタイムまたは実機を用意した時点で追加する。

XcodeのProduct > BuildとProduct > Testを通し、最後に「新規作成 → 編集 → 子作成 → 上位へ戻る → 終了・再起動 → 内容確認」の一連の操作を確認する。実機ではピンチ、日本語キーボード、シェイクによるUndoを確認する。削除後のUndo通知と明示的なUndo操作も用意する。

## 6. MVP後の順序

1. 親作成・上下のブランチ・リンク。未完の新しい親が既存の子を持つケースは、子の新規作成条件との違いを仕様として整理する。
2. 参照の共有・参照数・削除時の確認・発展。
3. アウトライン・タイムライン・ツリー表示、画像・テキスト書き出し。
4. CloudKit同期。競合時の修復と、同期途中の一時的な欠落を誤って修復しない条件を決めてから有効化する。

## 8. 最初の実装単位の実装結果（2026-09-25）

段階1〜3を実装。`NewDen.xcodeproj` の共有Scheme `NewDen` から起動・テストできる。

- iOS 26.0以降／iPhone／Swift 6言語モード。Bundle Identifierは `jp.ataraxia.NewDen`。実機用Teamは未設定。
- 4モデル、6種類の型、初版のVersionedSchema・SchemaMigrationPlan、ローカルModelContainer、Previewを追加。
- 一覧、作成、2×2編集、完了とキャンセル、バックグラウンド確定、型選択、未完表示、作成日時、Three Good Thingsの日付、削除、Undo／Redo、保存エラー再試行を実装。
- 子作成の条件と4階層上限をStoreで検証し、画面にも条件を適用。子へは通常のNavigationStackで移動できる。段階ズーム・入れ子配置・パンくずは段階4の対象。
- 型変更は「現在未完なら可」。最上位の削除は田んぼ全体を削除し、Contentの後片付けも同じUndoに含める。
- 初版スキーマは今回の保存範囲に限定。リンク・参照・発展の属性は将来のスキーマ移行で追加する。

### Undo実装の変更

計画していたSwiftData自動Undoでは、iOS 27 Simulatorで「新規Contentの編集をUndoするとDen.slotsが空になる」「cascade削除をUndoすると内部スナップショットのassertionで終了する」を再現した。保存や変更記録の順序を変えても解消しなかった。

そのため `ModelContext.undoManager` による自動登録を無効にし、操作ごとに対象の田んぼの値スナップショットをシステムの `UndoManager` へ登録する方式に変更した。1操作を1グループにし、UUIDを維持して関係を復元、Undo／Redo直後も明示的に保存する。保持範囲は操作対象の田んぼ（最大40個）であり、一覧全体を複製しない。将来、田んぼをまたぐ共有を追加する際はこの復元範囲も拡張する。
